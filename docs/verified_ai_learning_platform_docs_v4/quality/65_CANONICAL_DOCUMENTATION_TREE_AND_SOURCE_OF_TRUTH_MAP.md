# Canonical Documentation Tree and Source-of-Truth Map

## Purpose

This document is the exhaustive navigation catalog for the Markdown knowledge base used by engineers, NotebookLM, Codex, and MCP workflows. It complements the code repository hierarchy in `quality/56_COMPLETE_PRODUCTION_REPOSITORY_FILE_HIERARCHY.md`. The goal is deterministic context discovery: an agent should know which document governs a decision before editing code.

## Source-of-truth precedence

1. Accepted ADRs and explicit domain/security invariants.
2. Canonical domain, architecture, data, AI, learning, security, and product specifications.
3. Engineering standards and repository hierarchy.
4. Phase and sprint execution documents.
5. Roadmap and descriptive/supporting documentation.

A sprint may refine execution but may not override a higher-precedence invariant without updating the canonical document/ADR in the same change.

## Folder responsibilities

- `product/` — Product promise, personas, user journeys, features, monetization.
- `domain/` — Canonical vocabulary, aggregates, bounded contexts, events, invariants, curriculum and math semantics.
- `architecture/` — System/runtime/API/async/error contracts.
- `ios/` — Native iOS architecture, UX, networking, persistence, auth, StoreKit, localization/accessibility.
- `backend/` — Spring Boot modular-monolith architecture, module boundaries, authorization, internal tools.
- `data/` — PostgreSQL, retention, storage/cache, training-data lineage.
- `ai/` — AI routing, prompts, verification, evaluations, costs, model evolution/governance.
- `learning/` — Mistakes, mastery, adaptive planning, exams and pedagogy.
- `security/` — Threat model and student privacy.
- `operations/` — SLOs, CI/CD, incidents, analytics, flags, FinOps, release trains, backlog promotion, technical debt.
- `quality/` — Testing, Codex standards, DoD, dependencies, hierarchy, workflow, AI gates, requirement traceability.
- `roadmap/` — Product and technical roadmap, program structure, Production V1 capability coverage.
- `integrations/` — NotebookLM/Codex/MCP context and handoff rules.
- `adr/` — Accepted architecture decisions.
- `sprints/` — Executable Phase/Sprint production delivery contracts.
