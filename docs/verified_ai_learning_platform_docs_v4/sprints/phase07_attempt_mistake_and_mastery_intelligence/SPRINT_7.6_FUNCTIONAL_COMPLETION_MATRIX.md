## 2. Sprint 7.6 Operational Runbook

### 2.1 Feature Flag & Default Configuration
- **Configuration Property:** `verifiedai.mastery.evidence-stratified-enabled` (environment variable `MASTERY_EVIDENCE_STRATIFIED_ENABLED`, default `false` in `services/api/src/main/resources/application.yml`).
- **Default Runtime Posture:** Disabled (`false`) by default in local, test, and production profiles until owner acceptance and release authorization complete.

### 2.2 Enablement Prerequisites
Before setting `MASTERY_EVIDENCE_STRATIFIED_ENABLED=true` in any shared environment:
1. Sprint 7.5 full owner acceptance (`bash scripts/quality/sprint_7_5_owner_acceptance.sh --full`) and Sprint 7.6 full owner acceptance (`bash scripts/quality/sprint_7_6_owner_acceptance.sh --full`) must both achieve `LOCAL_ACCEPTANCE_PASSED`.
2. Flyway migration `V038__evidence_stratified_mastery_and_prerequisite_edges.sql` must be applied cleanly on top of `V037`.
3. Owner release authorization must be granted.

### 2.3 Legacy `bkt-lite-v1` vs. `bkt-lite-v2` Compatibility
- Both versions coexist in `learner_skill_mastery` under `(user_id, skill_id)` with `ck_mastery_policy` (`mastery_version IN ('bkt-lite-v1','bkt-lite-v2')`).
- When `MASTERY_EVIDENCE_STRATIFIED_ENABLED=false`, `LegacyMasteryWriter` continues updating `mastery_version='bkt-lite-v1'` rows (`attempt-skill-v1:<MistakeCode>`) for backward compatibility, and `GET /api/v1/mastery/skills` returns `enabled: false` with empty `skills` and `outcomes`.
- When `MASTERY_EVIDENCE_STRATIFIED_ENABLED=true`, `LegacyMasteryWriter` is suppressed so new evidence writes exclusively to `mastery_version='bkt-lite-v2'` via `MasteryApplicationService`. Historical `bkt-lite-v1` rows remain untouched and readable.

### 2.4 Migration `V038` Verification
- Verify `flyway_schema_history` records version `038` (`evidence_stratified_mastery_and_prerequisite_edges`) with `success = true`.
- Verify `solution_learning_disclosures`, `attempt_mastery_context`, `learner_skill_mastery_transitions`, and `mastery_prerequisite_edges` exist with their immutability and invalidation triggers.

### 2.5 Handling Evidence Correction, Dispute & Deterministic Replay
- When a learner submits a mistake dispute (`LearnerMistakeDnaService.dispute`), an OCR step correction (`AttemptStepOcrCorrectionService.correct`), or a superseding structured work revision, database trigger `invalidate_mastery_projection()` immediately deletes cached `mastery_version='bkt-lite-v2'` projections for that `user_id`.
- Subsequent `MasteryApplicationService.read(owner)` or `MasteryEvidenceChanged(owner)` events acquire `store.lock(owner)`, read all currently valid, non-disputed, non-superseded evidence from `AttemptMasteryEvidenceSource`, and deterministically rebuild `bkt-lite-v2` skill states from prior `0.25` in `(observedAt, attemptId, evidenceId)` order.

### 2.6 Duplicate Event Suppression & Unsupported Historical Evidence
- Every transition carries a deterministic `evidence_fingerprint` and `evidence_id` under `UNIQUE(user_id, canonical_skill_code, policy_version, evidence_fingerprint, evidence_id)` in `learner_skill_mastery_transitions`. Duplicate deliveries or concurrent reads under the owner lock produce a single projection and a single transition audit row.
- Historical attempts and drills created before `V038` that lack a complete `attempt_mastery_context` row (`provenance_complete = true` and matching `captured_at`) are classified as `UNSUPPORTED` and never modify `posterior_score` or `independent_competence_score`.

### 2.7 Investigating Failed Mastery Transitions
- Inspect `learner_skill_mastery_transitions` for `user_id` ordered by `event_time, id` to audit `evidence_type`, `prior_score`, `posterior_score`, `prior_half_life_days`, `posterior_half_life_days`, `evidence_fingerprint`, and `provenance`.
- Inspect `attempt_mastery_context` for `(user_id, attempt_id)` and `solution_learning_disclosures` for `(user_id, problem_session_id)` to verify `solution_revealed`, `hints_used_count`, `tracking_complete`, and `provenance_complete`.

### 2.8 Non-Destructive Rollback & Preserved Data
- **Immediate Rollback Action:** Set `MASTERY_EVIDENCE_STRATIFIED_ENABLED=false` and restart/redeploy the API configuration.
- **Effect:** Returns `enabled: false` from `GET /api/v1/mastery/skills`, stops `bkt-lite-v2` rebuild computation, and re-enables legacy `bkt-lite-v1` updates.
- **Preserved Data:** All `learner_skill_mastery` (`bkt-lite-v1` and `bkt-lite-v2`), `learner_skill_mastery_transitions`, `attempt_mastery_context`, `solution_learning_disclosures`, and `mastery_prerequisite_edges` rows remain intact in PostgreSQL; no destructive down-migration is ever executed.
