## 7 AI economics / proprietary-model guardrail answers

1. **Does this add or multiply an inference call?** No. Sprint 10.7 adds `0` AI/LLM inference calls (`llmTokensUsed = 0`, `inferenceCostUsd = 0.00`). All flag evaluation, SHA-256 bucketing, ETag hashing, and experiment assignment persistence are 100% deterministic Java and PostgreSQL operations.
2. **What is the expected invocation rate per learner action?** `0` inference invocations per learner action; client bootstrap/foreground refresh hits `GET /api/v1/config/remote` with `If-None-Match` (`304 Not Modified` on unchanged configuration).
3. **Can deterministic code/cache remove the call?** Yes—flag evaluation (`DeterministicBucketingPolicy`, `FeatureFlagEvaluationPolicy`), strong `ETag` conditional caching (`304 Not Modified`), and local file-protected iOS caching eliminate unnecessary payloads and involve zero AI calls.
4. **Can an economy-tier approved route satisfy the task?** Not applicable; zero AI routes are called. Routing percentages (`strong_model_pct = 0`, `proprietary_canary_pct = 0`, `secondary_solver_enabled = false`) serve purely as server-authoritative control configuration and cannot bypass `VerificationPolicy` (`domain/10_DOMAIN_INVARIANTS_AND_BUSINESS_RULES.md`) or golden-dataset evaluation (`ai/28_AI_EVALUATION_AND_GOLDEN_DATASET.md`).
5. **Is a secondary solver actually required, and what triggers it?** No secondary solver is invoked by Sprint 10.7. `secondary_solver_enabled` is seeded as a server-only `KILL_SWITCH` (`client_safe = FALSE`, `enabled = FALSE`, `rollout_basis_points = 0`) so operators can shut down secondary escalation immediately during cost/provider incidents (`operations/49`).
6. **What telemetry will reveal cost regression?** `FeatureFlagMetrics` records `verifiedai.featureflags.evaluated.total`, `verifiedai.featureflags.kill_switch.toggled.total`, `verifiedai.featureflags.experiment.assigned.total`, and `verifiedai.featureflags.admin.mutation.total`, while immutable `feature_flag_audit_logs` captures every rollout or routing change with `actor_user_id`, `reason`, `before_state_json`, `after_state_json`, and `correlation_id`. `proprietary_canary_pct` and `secondary_solver_enabled` remain audit-gated and do not replace golden evaluation (`ADR-005`).
7. **Does this create data that might later be useful for training?** No; per `adr/ADR-006_PRODUCTION_STUDENT_DATA_NOT_TRAINING_DATA_BY_DEFAULT.md`, all 4 `V071` tables enforce `training_eligible BOOLEAN NOT NULL DEFAULT FALSE CHECK (NOT training_eligible)`, schemas/DTOs enforce `trainingEligible = false`, `feature_flag_audit_logs` contains zero learner content or PII, and `experiment_assignments` cascades on `users(id)` deletion.
